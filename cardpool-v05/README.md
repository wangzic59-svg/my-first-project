# 金铲铲卡池助手 V0.5 · 实时数据分析版

Android 8.0+，包名 `com.example.cardpool`，版本号 5 / `0.5-realtime`。
本工具是离线的手动观察分析助手，不读取游戏进程，不使用 ROOT 或注入，不知道服务器的真实下一店结果。

## 使用

1. 安装 `downloads/JCC_CardPool_0.5.apk`。覆盖安装须与已安装版本签名一致，**不要先卸载旧版**，卸载会删除应用数据。
2. 从“卡池统计 → 配置赛季完整卡池与刷新规则”录入当前赛季的完整名单、费用、各英雄卡池总量和 1–11 级刷新概率。每级五个百分比合计 100，未知等级可全 0。核实完整同费名单后勾选确认。
3. 在“八人数据”分别编辑等级、金币、血量、持牌英雄、星级、个数和装备。每行格式 `英雄ID,星级,个数,装备`；2 星每个折算 3 张基础卡，3 星每个折算 9 张。装备记录不改变卡池权重。
4. 选择目标英雄与预测玩家，在“商店预测”查看单格概率、一店至少一张的概率、期望张数和金币可付费刷新次数。
5. 授予悬浮窗权限后可在八人、卡池、预测和快编页切换。快编的 ± 只增减一星无装备目标英雄；点玩家按钮可打开完整编辑。
6. “切换手动 / 模拟实时数据”开启隔离的示例，每 2 秒更新模拟金币、血量和观察数量。界面始终标记模拟来源。退出模拟恢复原手动数据，模拟不会覆盖手动存档。

不内置未经核实的官方赛季名单或刷新表。可以先进入模拟模式体验完整预测，但模拟英雄与规则不是实际赛季。

## 数据与兼容

- `DataManager` 是主界面和悬浮窗共享的进程内单一数据管理器；每次保存都从最新快照事务修改，验证成功并同步持久化后才通知双方重新渲染。没有缓存的计算结果字符串。
- 编辑器打开后若其他界面已更新数据，保存会提示重新打开，避免旧表单覆盖新记录。
- V0.4 的 `card_pool_form` 中 `p0`–`p7` 数量、等级、血量、阵容及装备文字迁移到 V0.5；兼容更早的 `self` / `other`。未归属观察不会再次分配给对手，避免重复计数。
- 原始偏好键不删除，新存档使用独立的 `state_v05_manual`。读取失败不会静默重置或覆盖旧数据。旧版没有保存数据来源信息，因此导入后标记“来源待核实”。旧版费用与完整名单未知，需用户补齐才启用新预测。
- 用户数据留在应用私有目录，不随源码或 APK 上传 GitHub。稳定英雄 ID 用于关联持牌；不可删除仍被引用的英雄。数据同步是本机两个界面的同步，不是跨设备或自动读取游戏。
- 本次 APK 沿用当前环境既有 Android 调试签名，已确认与环境中的 V0.3 APK 一致；未提供 V0.4 APK，无法对其证书作独立比对。覆盖更新依赖原签名；源码重建请使用你保管的原密钥。签名私钥不上传仓库。

## 概率模型

目标剩余 = 该英雄赛季总张数 − 八人全部已观察基础卡张数 − 未归属基础卡张数。
同费分母 = 完整同费英雄名单中各英雄估算剩余的合计。
单格概率 = 当前玩家等级对应的费用概率 × 目标剩余 / 同费剩余。

可选规则：

- 默认：每格先按固定概率抽费用，同费用内无放回。用二项分布混合超几何分布计算一店至少一张的概率，C++ 确定性计算，没有随机生成商店。
- 独立格有放回近似：一店至少一张 = `1 − (1 − 单格概率)^格数`。

这两种模型只适用于所声明的规则。不支持空费用重新分配、特殊赛季机制或保底机制；默认模型在任何正概率费用卡池不足一店格数时拒绝预测，避免暗自猜测耗尽处理方式。观察数超过总量、缺少名单、等级未知、刷新表无效时均明确显示预测不可用，不保留旧概率。

未看到的对手持牌与商店占卡不自动扣除；淘汰、出售、转录等变化需要人工更新。结果是基于观察的估算，与真实商店结果分开。装备不提供隐藏概率加成。

## 架构

- `GameState`：八人、英雄定义、持牌星级与装备、未归属观察、赛季规则的可验证快照。
- `DataManager`：事务、存储、来源隔离、订阅通知；主界面与悬浮窗均使用它。
- `DataSource.Manual` / `Simulated`：手动及确定性模拟来源。
- `DataSource.AuthorizedRecognition`：为后续经授权画面识别预留接口，当前没有 OCR 或自动识别实现。
- `NativeEngine` / `engine.hpp` / `jni.cpp`：C++ 卡池校验及概率处理，通过 JNI 调用，构建四种 ABI 并采用 16 KB ELF 对齐。

## 构建与测试

Linux 环境需要完整 JDK 21（包含 javac 和 JNI 头文件）、Python 3、C++ 编译器、Android SDK 35 / Build Tools 35.0.0、NDK r27c（27.2.12479018）。Gradle wrapper 为 8.13，包含分发校验和。

```bash
export JAVA_HOME=/path/to/jdk-21
export ANDROID_HOME=/path/to/android-sdk
export ANDROID_NDK_HOME=/path/to/android-ndk-r27c
export PATH="$JAVA_HOME/bin:$PATH"
bash scripts/test.sh
bash scripts/prepare_signing.sh   # 首次演示构建生成本地调试密钥；升级须使用原密钥
./gradlew :app:assembleDebug :app:lintDebug
```

如原密钥在其他位置，可设置 `CARDPOOL_KEYSTORE`；当前调试配置使用 Android 调试密钥标准别名和口令。生产分发应另行配置自己的签名，不要把私钥提交到仓库。

本地构建输出 `app/build/outputs/apk/debug/app-debug.apk`；公开仓库中的预构建包位于 `downloads/JCC_CardPool_0.5.apk`。工作流只运行测试并上传 Actions 构建产物，不创建公开 Release，不上传用户数据或签名私钥。

测试包括 C++ 的 605 组枚举概率对照、Java/JNI 的迁移/星级/保存失败回滚/来源隔离/同步通知检查，以及保留的 V0.4 算术与快捷编辑回归测试。详见 `BUILD_REPORT.md`。本次没有连接真机或运行 Android 模拟器，因此尚未验证厂商后台限制和实际悬浮窗交互；签名及结构检查不替代设备测试。
