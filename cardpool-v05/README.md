# 金铲铲卡池助手 V0.6 · 授权屏幕采集版

在原 V0.5 项目目录内增量升级，包名仍为 `com.example.cardpool`，versionCode=6。保留手动八人面板、悬浮窗快编、数据双向同步、模拟模式、赛季规则和 C++/JNI 概率模块。

## 安装与下载

GitHub Actions 工作流 `CardPool V0.6 build and screenshot tests` 实际构建 Debug APK，运行 Android 15 模拟截图 OCR 和真实悬浮窗同步测试。成功后将 APK 写入本开发分支的 `downloads/JCC_CardPool_0.6_actions.apk`，报告位于 `reports/ocr-accuracy.txt`，完整测试结果在工作流构建产物中。

Actions 的临时调试密钥与之前本地 V0.5 密钥不同，不能直接覆盖不同签名的旧安装。**不要为绕过签名检查卸载旧版**，卸载会清除用户数据。本地构建仍支持通过 `CARDPOOL_KEYSTORE` 使用原密钥。未将签名私钥提交公开仓库。

## 开始识别

1. 先保留或配置 V0.5 的完整英雄卡池、费用和等级刷新规则。
2. 在“采集 → 校准识别区域与8名玩家别名”配置当前画面比例、唯一玩家名称/编号（0–7）和相对坐标。默认 JSON 只是格式示例，不是官方游戏布局。玩家名字必须完整可见、能唯一对应八人；不支持按位置猜测当前玩家。
3. 区域键：`player`、`gold`、`level`、`hp`；`shop.0`–`shop.4` 表示当前可见商店名称；`board.0.hero` / `board.0.star` / `board.0.equipment` 等表示实际可见棋盘位置。坐标为 `[left,top,right,bottom]`，范围 0–1。
4. 金币、等级、血量、可见英雄名称及装备文字用捆绑的中文 ML Kit 模型在本机识别。英雄名必须精确匹配赛季名单；装备名称必须配置 `equipment` 别名映射。
5. 棋盘英雄通常没有名字文本。对图标区域使用“从截图录入模板”：选一张经你授权使用的截图，选择区域键及英雄ID/星级1–3/装备名称，裁剪保存本地模板。模板相似度≥0.97且第一/第二候选差≥0.04才产生候选。不附带未经验证的赛季英雄美术资产；须自行校准。
6. 先用“验证一张截图”查看结果与置信分。导入验证不写入对局记录。
7. 点“开始”并完成 Android 系统的 MediaProjection 授权。没有授权不捕获；服务非导出且不自动重启。通知栏和采集页可暂停、恢复、停止。暂停断开截图 Surface；停止释放 MediaProjection，下一次必须重新授权。
8. 前台服务每约1.5秒最多处理一帧，不保存完整实时截图；OCR只处理配置区域，Bitmap随后释放。应用移除联网权限，不上传截图。模板与观察记录留在应用私有目录。

## 置信度、数据保护和卡池

- 展示 OCR 引擎置信分或模板相似度分；这些分数不是经过真实游戏数据集校准的准确率概率。没有真实游戏截图，因此不能承诺开箱即用或真实对局准确率。
- 玩家身份分≥0.92、字段分≥0.90且同一玩家连续两帧一致才确认观察。未知身份、模糊文字、不完整字段、不符合数值范围的数据不会猜测或覆盖。
- 观察与原手动数据分开保存，包括时间与置信分，超过30秒标记历史；低置信/未稳定候选只进入待确认说明，不是有效数值。
- 开启“自动合并数值”后，仅未锁定的金币/等级/血量可自动更新。旧版已有数值与后续手动修正默认锁定；可以明确解锁所选玩家。棋盘/装备不会覆盖可能含备战席的完整手动记录。
- 可选“可见棋盘参与卡池估算”：只有英雄和星级同时双帧确认的可见棋子参与下界统计。每名玩家、每英雄在完整手动记录与可见棋盘下界中取较大值，不重复相加；手动修正的持牌可锁定。历史可能过期、不可见备战席未扣除，始终标注为估算。
- 当前可见商店独立记录，不能当作已购买持牌，也不当作“下一轮商店”。预测页支持多个目标英雄，沿用 V0.5 可配置赛季及刷新规则，不提供精准预知。
- 主界面和悬浮窗共用原 `DataManager`，每次合并通知双方渲染最新状态；悬浮窗新增“观察”页，保留原四页。

## 数据升级与测试

继续使用原 `state_v05_manual` 和 V0.5 序列化 UID，新增的可选观察字段在读取旧数据后初始化。包含用原 V0.5 类真正序列化产生的测试存档，验证旧英雄、星级、装备、金币等保留。不会删除旧存档。

运行：

```bash
# JDK21、Python3、C++、SDK35/Build Tools35、NDK r27c；详见 docs/V05_README.md
bash scripts/test.sh
bash scripts/prepare_signing.sh
ANDROID_NDK_HOME=/path/to/ndk bash gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
# 有连接的 Android 设备/模拟器：
bash gradlew :app:connectedDebugAndroidTest
```

本地纯模块测试包含原 V0.5 的 605 组 C++ 概率对照、33 项 Java/JNI 回归和 V0.6 的30项置信度/玩家关联/旧存档/八人通知/手动保护/模板检查。Android 测试实际运行捆绑 OCR 引擎识别12张合成画面，记录金币/等级/血量精确匹配率、身份和语义字段识别数；测试真实悬浮窗服务收到八人更新后的修订号，并验证授权拒绝不会启动采集。合成截图不是实际游戏画面，统计不能替代真实游戏准确率。

暂未完成真实设备上用户授权采集的完整交互、各手机厂商保活、真实游戏图标/装备/玩家名称样本的验收。识别布局、模板质量、遮挡和语言会影响效果。见 `docs/SHOP_MECHANISM.md` 和构建报告。
